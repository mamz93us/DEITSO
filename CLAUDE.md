# CLAUDE.md — Conventions for AI contributors

This file codifies the non-negotiable rules verified during the V1 cross-sprint
security audit. Read it before changing any tenancy, action, or persistence code.
The authoritative product spec is [PROJECT.md](PROJECT.md); this file is the
operational complement.

## 1. Tenant isolation is sacred

- Every tenant-owned table has `organization_id`. The model uses the
  `App\Models\Concerns\BelongsToOrganization` trait, which applies the
  `App\Models\Scopes\OrganizationScope` global scope.
- The active org is bound by `SetActiveOrganization` middleware as
  `app('current.organization')`. Do NOT read it via `Auth::user()->...` — the
  binding accounts for system admins acting across orgs.
- Defensive default: if the binding is missing and the user is not a system
  admin, the scope emits `WHERE 1 = 0`. Tests asserting "no leakage" rely on
  this — do not relax it.
- For models that don't carry their own `organization_id` (e.g.
  `AssetRemoteAccess` scopes via parent `Asset.organization_id`), wire the
  scope explicitly via `whereExists()` on the parent. Look at
  [app/Models/AssetRemoteAccess.php](app/Models/AssetRemoteAccess.php) for the
  canonical pattern.
- Action classes that accept foreign IDs (technician, requester, etc.) MUST
  validate the ID belongs to the same org as the parent entity. See
  [app/Actions/Visits/ScheduleVisit.php](app/Actions/Visits/ScheduleVisit.php).

## 2. Business logic lives in Actions

- `app/Actions/<Module>/<VerbNoun>.php` — single public `__invoke` (or named
  method), wrapped in `DB::transaction(...)`, returns a typed array or DTO.
- Errors: throw a domain exception (e.g. `HrTaskBlockedException`) for soft
  failures with context. Let unhandled `\Throwable` propagate after recording
  failure state — never swallow.
- Side effects (email send, WhatsApp, PDF generation) happen via queued Jobs
  dispatched from the action, not inline.
- Activity-log via Spatie: declare `logOnly([...])` on the model. Never log a
  decrypted credential.

## 3. Secrets stay encrypted at the model layer

- Use the `encrypted` Eloquent cast on every secret column. The convention is
  `*_encrypted` in the column name (e.g. `api_token_encrypted`,
  `password_encrypted`). Accessing the property returns the decrypted value —
  Laravel handles the round-trip.
- Never `dd()`, `var_dump()`, or `Log::info()` a decrypted secret. The
  `$hidden` array on the model must include the encrypted column to prevent
  accidental serialization.
- Viewing decrypted credentials in the UI requires its own Spatie permission
  (see Filament Shield bindings).

## 4. Database access uses Eloquent

- No raw `DB::statement(...)` with interpolated values. Bind parameters or use
  the query builder.
- `DB::raw(...)` is only acceptable for literals (constants like `1`,
  `NOW()`). Anything user-supplied must go through bindings.
- N+1: prefer `with(...)` eager loading on relationship-heavy resource pages.
  Use `Model::lazy()` / `chunk()` for large iterations.

## 5. Filament conventions

- Resources auto-discover under `app/Filament/<Panel>/Resources`. Three panels:
  `App` (org admin), `System` (platform admin), `Portal` (end-user, read-mostly).
- Permissions are auto-generated by `bezhansalleh/filament-shield`. Run
  `php artisan shield:generate --resource=<Name>` after adding a resource.
- Long lookup `Select` fields use `->searchable()->getSearchResultsUsing(...)`
  with an explicit `limit()`. Avoid `->options(Model::pluck(...))` on tables
  that grow with usage (assets, employees, tickets).
- For state machines (Request, Ticket, HrProcessTask), use
  `spatie/laravel-model-states`. Transitions go through Action classes — never
  flip a status column directly.

## 6. Rate limiters

Named limiters live in `app/Providers/AppServiceProvider::configureRateLimiters`.
Today:

- `filament-auth` — 5/min per IP on login/password-reset/email-verification
  paths across all three panels.
- `internal-callback` — 60/min per IP on `routes/internal.php` (Caddy on-demand
  TLS check), in addition to token + IP-allowlist gates.

If you add a new public endpoint, register a limiter rather than relying on
Laravel's generic global limiter.

## 7. Testing

- Pest, with `RefreshDatabase`. In-memory SQLite for speed.
- Feature tests (`tests/Feature/<Module>/`) cover Actions end-to-end and should
  assert: happy path, the auth/tenant guard, the activity-log row, and at least
  one failure mode.
- Provider HTTP clients (cPanel, GoDaddy, Green API) use Guzzle `MockHandler`
  + `Middleware::history` to assert wire format. See
  [tests/Feature/Domains/GoDaddyProviderTest.php](tests/Feature/Domains/GoDaddyProviderTest.php)
  and [tests/Feature/Email/WhmCpanelClientTest.php](tests/Feature/Email/WhmCpanelClientTest.php).
- Pest is the default; PHPUnit-style tests are allowed but new tests should be
  Pest where reasonable.

## 8. Style

- `declare(strict_types=1);` on every PHP file. Pint enforces this in CI.
- Imports alphabetized; no unused imports; no `?:` short ternary on nullable
  arrays (Pint will rewrite it).
- Run `composer pint` before pushing. CI runs `pint --test`.

## 9. Code-comment policy

- Default to **no comments**. Well-named identifiers and small functions are
  self-documenting.
- Write a comment only when the *why* is non-obvious: a hidden constraint, a
  subtle invariant, a workaround for a specific bug.
- Never describe *what* the code does. Never reference the current task,
  reviewer, or PR number — that belongs in the commit message.

## 10. Things that get a security review by default

If your change touches any of these, request a security review before merge:

- A new tenant-scoped model (does the scope work? is `organization_id` indexed?)
- A new Filament resource (does it inherit the panel auth + throttle? does it
  expose any cross-tenant relationship?)
- A new public route in `routes/web.php`, `routes/api.php`, or `routes/internal.php`
- Any change to `OrganizationScope`, `SetActiveOrganization`,
  `SetSpatieTeamContext`, or `ResolveOrganizationFromHost`
- Any new third-party HTTP client or webhook receiver
- Any change that adds or removes an `encrypted` cast on a model field

When in doubt, read [PROJECT.md §3 Architectural Rules](PROJECT.md) — they are
non-negotiable.
